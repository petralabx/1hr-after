# MC routing metadata (shadow)

`.github/workflows/mc-routing-metadata.yml` (generated by PLX_MC `scripts/generate-routing-workflow.py`; do not edit) sends PR metadata only (no checkout, no PR code execution) to Mission Control using GitHub OIDC. It is advisory and never affects the compliance gate.

## Files

- `.github/plx-mc-routing-manifest.json`: verbatim fleet template (sha256 `38176edb…8d07`, matches the PLX_MC registry digest).
- `.plx/mc-routing.json`: local declaration. Default Bucket `BKT-INFRA`, no path rules (not consumed by the runtime), fuzzy auto-link off.

## Variable and rollback

- Enable: set repository variable `PLX_MC_ROUTING_METADATA_ENABLED=1`. The job runs only on exactly `1`.
- Rollback: unset the variable or set it to anything other than `1`. The job is skipped; no file change is needed.
- Destination comes from `PLX_MC_BASE_URL` (variable or secret) and must be `https://mc.plxcustomer.io`.

## Shadow mode

This repo is a `shadow` cohort in PLX_MC (`config/routing-pilots/1hr-after.json`). Mode, candidate visibility and fuzzy auto-link (`PLX_MC_ROUTING_FUZZY_AUTOLINK_ENABLED`) are central runtime settings. In shadow the workflow summary shows no candidates and no deep link; a link is only rendered when MC returns `effectiveMode: "suggestion"`. Fuzzy auto-link stays off.

## Operator verification after merge

1. Set `PLX_MC_ROUTING_METADATA_ENABLED=1` and confirm `PLX_MC_BASE_URL` is set.
2. Confirm the workflow has `id-token: write` and GitHub OIDC is available for the repo.
3. Open or reopen a PR; check the "MC Routing Metadata" run summary says metadata was recorded, with no link.
4. In MC, confirm a shadow proposal and audit event exist for the PR, with no visible candidates or deep link.
5. Unset the variable and confirm the next PR event skips the job (rollback proof).
